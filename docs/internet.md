# AW1000 双线、DNS 与 IPv6（1.2.4）

## 上网设置

页面只保留线路模式、当前出口、两路状态、应用和 120 秒确认/回退。展开详情查看 DNS、IPv6、探测间隔/次数、蜂窝字节计数、上次切换和同步代次。WAN 接入参数统一在“网络 → 接口 → wan”配置，切换线路模式不改协议、账号、密码、VLAN 或 MTU。

| 模式显示 | 内部键 |
| --- | --- |
| 仅有线网络 | wired_only |
| 仅SIM卡上网（3G/4G/5G） | cellular_only |
| 有线网络优先，断网自动用SIM卡 | wired |
| SIM卡上网优先，断网自动用有线 | cellular |

应用复用现有事务/备份/120 秒确认；相同模式无变更时不重载。用户明确更改模式可提交必要配置；日常自动切换只更新 RAM，不改 /etc/config/mwan3 或整体重载 mwan3。

物理设备 lan1–lan4 / wan，逻辑接口 lan、wan、wan_v6、wwan、wwan_v6。移动底层 wwan0_1 等保持内核原名。默认 DHCP，PPPoE/VLAN 可在标准接口页面设置。

## 健康探测与低流量

管理 fw3 兼容 mwan3 2.11.7，按真正的公网 IP 连通性探测，不仅检查网线载波。光猫到 AW1000 网线不断而光纤断开时，也会通过连续失败判为不可用。

- 有线当前/恢复探测约 2 秒，连续失败 2 轮切出、成功 4 轮恢复；约 2–4 秒故障、6–8 秒恢复是通常时序，不是硬实时保证。
- 有线优先且有线健康时，备用蜂窝 60 秒一次；连续失败后退避到 120/300 秒。
- 蜂窝作为当前出口约 10 秒一次，仅 SIM 模式约 30 秒一次。
- 一轮先测一个 IP，成功结束，失败才尝试第二个；8 字节 ping payload，没有周期 DNS/HTTP/公网测速。
- 单线模式另一条健康 tracker 挂起，不发送探测；模块注册、PDP、DHCPv6 和 RJ11 保留，不能承诺运营商数据会话完全零流量。
- 从备用切入时撤销陈旧 online，按本次 WAN 故障代次完成重新验证；恢复的连续成功轮次用短间隔完成，避免“恢复检测中”循环。
- 静态角色/配置在进程内缓存，动态角色依赖 RAM selected/tracker；物理断线事件仍及时唤醒。

状态里 attempts 是探测目标尝试数，不是计费流量。蜂窝接口 rx/tx 包括业务和管理流量，不能仅用它估算探测成本。实际用量应以无客户端业务时的计数差与运营商账单复核。

## 路由维护

QConnectManager 辅助 udhcpc 不再建立无 metric 的移动 default 或删除有线 default，保留地址与非默认 classless route。netifd/mwan3 管理默认路由，route guard 限频修复主表与动态解析出的成员表。

修复必须满足接口 up、IPv4 有效、netifd 已发布 default；DHCP 缺少默认路由/网关时停止，不凭地址制造直连 default。已连接不等于公网可达，健康状态仍由 tracker 决定。

配置同步用持久文件哈希作为 RAM 缓存；有未提交编辑时延后。首次登记/必要修正只提交实际有变化的包。不能把自动切换变成周期提交配置或重拨。

## DNS 先行、IPv6 独立

协调器先发布 IPv4 选择、更新 DNS，再给独立 procd IPv6 worker 发送带代次请求。慢 IPv6、nft/odhcpd 错误不阻塞 DNS。

自动 DNS 从已发布出口读取 IPv4 DNS，追加 223.5.5.5、119.29.29.29；只接受有效 IPv4 单播地址。这些服务器仍可返回 AAAA，并非禁用 IPv6 查询。没有允许且可用的出口时不绕过单线策略。

只处理启用的 dnsmasq 自动实例。MosDNS enabled+redirect 或实例明确手动配置上游时，保留其解析接管；同一目录存在手动与自动实例时，以手动接管为准，避免写入共享目录污染自定义解析。按实例清单核对临时文件，旧目录只删除本工程拥有的 aw1000-mwan.conf，不清空整个 confdir。

配置原子替换；重启成功才发布成功签名。dnsmasq 重启最长 10 秒，失败按 5/15/30 秒退避；恢复文件或重启成功后重置失败次数。已经处于自定义接管且无残留工程文件时不反复重启 dnsmasq。

DNS、IPv6 各有状态与错误；snapshot.json 原子发布代次和时间。IPv6 worker 最长 12 秒处理一轮，出口代次改变或服务停止时取消旧子进程及其受管后代，失败 5/15/30 秒重试。内置静态 timeout helper，不依赖原 BusyBox 缺少的 timeout。快照反映各阶段提交时的状态，不声称跨内核/多个服务的全局事务。

## IPv6 策略与完整性

两路 DHCPv6 保持在线，只有已选出口可向 LAN 提供公网路径。PD 可用时使用下发前缀；没有 PD 但有上游全局地址和网关时，以本地 ULA 经 ip6tables SNAT/NAT66 上网。fe80 链路本地地址只用于本链路通信，ULA 不能原生路由到公网。

目标内核缺少 NF_TABLES_SET 与 nft IPv6 NAT 支持，所以 filter 前缀例外使用独立规则，SNAT 使用 ip6tables，不使用匿名集合或 nft NAT base chain。

每轮检查完整 policy rules、61000 表路由、nft 过滤器和私有 NAT 链。缺失/损坏时重建自己的对象；带所有权账本逐条删除规则/路由，不 flush 整张表或按优先级删除别人的规则。同名外来 nft/NAT 链、占用保留优先级/路由表而无所有权时拒绝接管，并报告失败。修复失败撤销 LAN 默认 RA，避免宣称错误出口已可用。

区分实际流量签名与备用维护例外：备用线路地址变化，只改 from/oif 例外，不反复重装当前 NAT、RA 或清连接。LAN 前缀、实际出口/源地址等改变时才执行完整协调；IPv6 conntrack 只按旧受管 LAN 源前缀逐连接删除，保留路由器自身及不匹配连接。失败的前缀清理留在 RAM 队列重试，不做全 IPv6 flush。IPv4 仍按旧成员 mark 定向清理。切换公网地址后原业务连接仍可能需要重建。

IPv6 network/dhcp 使用私有 RAM UCI 视图与限定 netifd/odhcpd preload，不向普通 /tmp/.uci 或 /etc/config 写运行时变更。基础配置文件改变会重新导出；实际管理器停止时按账本清理并恢复服务视图。

## 无线扫描与状态

旧 LuCI 在本机创建 tmpsta 会导致对应 QCA AP down，删除 tmpsta 后未恢复；接口 flags/iwinfo 可能仍声称在线。1.2.3 将 network.js、无线扫描对话框和信道分析改为 RPC 读取已有 scan dump；没有可用主动扫描能力时返回空缓存并提示限制，不进行隐藏回退。

单次请求有锁、4 秒读取超时、10 秒 RAM 缓存。扫描、按钮、WPS 共用无线锁；驱动事件按接口 ifindex 关联，过期接口事件不覆盖新接口。仅当扫描期间新出现匹配当前接口的 VAP down、无线配置未改变且未禁用时，限频一次单频恢复（15 秒上限、60 秒冷却），失败留日志，不循环。

这不是通用无线看门狗，不会定期擅自拉起用户关闭的 AP。缓存没有结果不代表周围没有无线网络。QSDK 临时 VIF 列表做局部去重，不宣称已查明所有原厂 uci: Entry not found 诊断的来源。

## 诊断与实机边界

`aw1000-dns-check` 默认只读；`--query` 才发查询。`aw1000-led-check` 查看灯、按钮、实际接口与驱动状态。上网设置展开详情提供运行代次、DNS 阶段、IPv6 结果与探测计数。

自动测试覆盖隔离的 UCI/ubus/路由/防火墙状态及成品原运行库，不替代设备测试。路由器自身查询 127.0.0.1 或本机 LAN IP 成功，不能证明 Windows 客户端请求已抵达路由器；历史客户端 TCP/UDP53 超时仍需现场抓包、INPUT 规则及客户端网络路径复核。

建议验收：双线正常启动、拔网线、光猫断光纤但网线不断、插回主线、两路皆断、四种模式、DNS/LAN IPv6、备用地址更新、重启及无线缓存读取。保留配置不重置旧密码，也不泛化清理自定义 DNS。

管理期间暂停 ECM 和通用流量卸载，保留 NSS/无线驱动，吞吐量可能降低。公开电话驱动 ABI、实际灯光、WPS 完整配对和 sysupgrade 自动复位继续保留真机验收边界。


## Modemdata 与现有网络服务

1.2.4 完整加入“移动网络信息”五页面，默认串口自动跟随 QModem 的有效 AT 端口、网络接口 wwan。它查询模块信息和已有接口计数，不设置 APN、默认路由、DNS 或线路模式；其连接状态表示数据会话，实际出口以 aw1000-internet 为准。

串口共享 at-daemon。动态信息至少 10 秒缓存，身份信息 300 秒；新采集最长 24 秒、失败退避 5 秒，失败时最多显示 60 秒前的动态结果并标注，超过则显示查询不可用。浏览器后台暂停、弹窗关闭停止定时器，没有额外后台轮询服务；原有 LED/RJ11 采样继续按各自机制运行。

定义模块和配置页面可手动保存；自动发现结果与查询缓存只在 RAM。读取信息不发送 ping/DNS/HTTP 探测，但用户主动选择外部基站/地图功能会访问网站。上游更新页目前只有说明和支持，未添加自动更新。

保留全部协议后端与页面，默认不启用新的 QMI/MM 管理进程。切换为其他协议前需核对现有拨号器和依赖，避免同时启用多个管理器；本次自动测试覆盖 AW1000 的串口队列路径，不证明其他协议/设备已真机兼容。
